# 监控刷新与终端输出调度

## 问题与范围

2.2.28 本机日志中，截图对应的群晖会话持续采集到 78 个有效样本，renderer
继续收到指标事件并记录 scheduled，但侧栏只记录首次健康样本摘要。日志没有记录
React 实际提交的 revision，无法仅凭现有记录断言具体卡住位置。

处理监控事件应用与终端输出消费的调度；不改变 SSH 传输、采集器、输入协议或凭据。
监控卡住与 CC 体感延迟是否同源，仍需要原生环境和长期运行复测。

## 实现

- 监控健康状态与样本不再作为低优先级 Transition 更新，保留原有 generation/revision
  和断线、乱序保护。
- 空闲终端立即向 xterm 提交首批输出；每批仍限制 16 KiB，解析回调完成后继续消费积压。
  不再依赖后台 WebView 可能暂停的动画帧；xterm 自己拥有绘制调度。
- 现有指标接收/调度与侧栏每分钟样本摘要日志增加 generation/revision 对照信息，不增加频率。
- 删除输出帧 ref 及相关生命周期、回放取消代码；旧解析回调通过终端身份与回放 generation
  保护，不得修改新生命周期的写入状态。
- 同分支修复横线断开与接缝粗细变化：`─`、`━`、`═` 不参与字形缩窄，复用块字符的
  逐行设备像素位图，从字符格几何绘制横线；其他溢出符号继续按原规则适配。
  参考 [Ghostty 线框绘制](https://github.com/ghostty-org/ghostty/blob/main/src/font/sprite/draw/box.zig)
  的几何栅格化方式，保留既有 ANSI/反色、选区颜色、背景和销毁处理。
- 流量图不再给补零历史后的首个真实样本人为添加 breakBefore，使初始基线接上采样曲线；
  继续保留采集器标记的真正恢复断点。

## 验证

- Node 定向测试：首批立即提交；暂停动画帧时按序消费并保留分批限制；旧回调隔离。
- 浏览器回归：真实 React IPC hook、系统侧栏、TerminalView/xterm；无键鼠操作下持续
  100 次监控更新；暂停动画帧后排空 200 个连续终端输出事件，并继续提交指标。
- Chromium 与 WebKit 浏览器回归通过；同一暂停动画帧场景在旧运行时代码上因输出
  无法排空而超时，验证回归能够捕获旧问题。
- 类型、lint、Prettier、45 个 renderer 测试、749 个 Rust/contract 测试、Clippy
  与 CSS contract 通过。CSS 检查仅保留既有的 11 处 !important 和 1 处颜色迁移债务。
- Rust 首次编译遇到磁盘空间不足；清理 target/debug/incremental 编译缓存后重跑通过。
- 横线回归先在旧代码复现：原生连续横线无缝隙，符号适配后出现 9 处断点。修复后在
  Chromium、WebKit 的 100%、125%、150%、200% 缩放及 14/24 字号下验证三种横线，
  覆盖独立 ANSI spans、合并文本、与溢出符号/CJK/组合字符混排，逐列检查像素粗细一致，
  并检查原始文本、部分选区前景、清除选区和绘制器销毁。
- 重跑原有 Chromium/WebKit 符号遮挡与真实鼠标拖选回归（包括块字符选区颜色），以及
  Chromium Cascadia 选区、中文标点网格、字体晚加载回归。流量图补零连接与真实断点
  通过单测，并在真实侧栏 IPC 浏览器测试中检查首个采样后的路径连续。
- 尚未完成原生安装包、真实 CC 会话和数小时连续运行验证，不能将调度修正等同于
  已确认消除所有无响应来源；Win10/Win11 原生横线显示仍需实机验证。
