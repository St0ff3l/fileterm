# SSH、SFTP 与目录传输回归修复

日期：2026-09-08。分支：`fix/ssh-and-transfer-stability`。

关联：Refs #234、Refs #239、Refs #240、Refs #241、Refs #226。

## 问题与处理

- **#234 大目录上传慢/黑窗口**：当前分支已节流目录日志和进度事件，但 UI 投影仍先深拷贝整个 manifest 再清空，事件路径继续额外拷贝大任务。改为直接构造小型投影；只有启动执行时返回完整任务。目录条目开始、完成、失败都按索引写回内存，避免每个小文件拷贝整棵树，也修复 Silent 更新使活动条目落后于真实文件的问题。多文件批量创建不再调用空的占位 `queueUpload`，也不逐个应用完整 workspace snapshot，批次结束只应用最后一个成功快照；传输进度继续通过独立事件增量更新。journal 的序列化和 fsync 放入 blocking pool，写锁随 blocking 任务持有，调用方取消也不会造成并发写入。
- **#239 文件夹上传**：保留文件区原有的单个上传按钮，不增加第二个文件夹按钮。文件夹可通过现有原生拖放路径进入同一 Rust manifest 传输流程；文件选择器继续上传文件。当前分支对符号链接、Windows Junction 和不可读目录的显式报错行为继续保留，避免静默漏传。
- **#239 SFTP 显示区不刷新**：shell 每次提示符都会报告 CWD，但过去只有路径改变才发起目录读取。现在相同 CWD 的新提示符也刷新 SFTP 列表；使用单个活动请求和一个最新待处理请求，合并 200ms 内的提示符重绘。跟随关闭时保持原有不自动导航行为；没有 shell integration 的会话仍需手动刷新。读取结果返回时核对目录和权限模式，避免覆盖后来手动导航或切换权限的结果。
- **#239 启动竞态**：SFTP 协商晚于终端启动时，Shell CWD 可能先被记录而无法入队刷新。辅助通道就绪边界会重放当前 Shell CWD，确保初始目录列表完成后文件区跟随到最新路径。
- **#240 容器用户名误判**：SSH 配置 username 可能是容器/网关路由标识，不能当作远端 Unix 登录用户。首次 runtime `RemoteUser` 标记建立真实登录身份，普通文件操作保持 SFTP；真正的后续 sudo/su/exit 仍同步文件权限。Exec 与资源监控开关不再因路由用户名差异导致文件区误切到 root exec。
- **#240 root 文件读取噪声**：root 视图仍需通过 sudo/su 的独立 exec 通道读取文件；读取命令现在用起止标记包裹 base64 正文并隐藏 stderr，sudo 提示或 PTY 噪声不会再进入解码器，空文件也能稳定返回空内容。
- **#240 SFTP 失败状态**：SFTP 握手超时或被拒绝时，文件能力降级并同步结束 `remote_files_loading`，文件区不会永久停留在加载态。
- **#241 UTF-8 损坏**：stdout/stderr 各自采用跨包 UTF-8 解码器，不完整字符保留至下个数据包；非法字节替换不会吞掉后续未完成字符。只有完整字符串进入 shell 过滤和终端 batch，timer flush 不再截断字符；EOF 释放残留字符。
- **#226 Copilot 空密码字段**：当前分支已有无凭据工具 schema 和忽略旧敏感字段的修复。本次增加普通只读命令带空串、null、空白 sudo/su 字段的回归，确认不会因 SSH 密钥登录而要求重新提供登录密码。
- **Kubernetes 连接预设与认证布局**：新增 `Kubernetes 模式` SSH 认证预设，沿用密码认证协议但保留容器 ID 作为 SSH 用户名；导入配置可识别该模式。认证表单将方法单独铺满一行，用户名与登录密码并排，sudo/su 密码并排，并在模式下说明 `ssh -l <容器ID> <主机> -p <端口>`、容器内实际 shell 用户可能是 root，以及文件区使用 SFTP、Exec 用于后台命令和资源监控。
- **连接主机慢**：主 shell 建立后立即发布连接状态并运行终端输入/输出循环，平台探测、SFTP 初始化和指标启动并行进行。连接成功路径不再同步等待完整 workspace snapshot（它还会触发传输日志 hydration、连接库和命令库读写），快照改为后台构造并按 revision 与后续辅助快照安全合并；辅助初始化结束不关闭终端，终端退出会取消本次连接的后台任务。连接日志记录认证完成、shell channel ready、terminal ready 三个耗时边界，便于区分网络握手与本地初始化延迟。用户已开始输入时跳过延迟的初始 shell 注入，避免脚本混入用户正在输入的命令。

## 影响层与职责

不新增协议客户端或 IPC 类型。修改 Rust SSH worker、transfer service、SSH 认证类型映射，并复用现有 renderer 上传入口、bridge 与 core 类型；连接表单只新增一个可持久化的 SSH 认证预设。

SSH worker 的 `event_loop.rs` 从 819 行拆为 450 行事件编排与独立的 `shell_data.rs`；`loop.rs` 从 493 行拆为 300 行连接编排与 `auxiliary_startup.rs`。新增 `startup_lifecycle.rs`、`utf8.rs`、`cwd_refresh.rs` 分别承担启动生命周期、解码和刷新队列。以上均为非豁免业务文件，保持在 800 行以内；不是触发 1000 行阈值后的机械拆分。

## 验证

- UTF-8：多字节横线、中文、emoji、OSC 的所有分割位置和逐字节输入；非法字节后接未完成字符；stdout/stderr 独立；EOF。
- SSH 生命周期：辅助通道永久挂起时，普通输入和 Ctrl+C 仍有输出；主循环退出会释放初始化任务；辅助初始化完成不会关闭终端。
- 身份与提示符：容器实际 root 用户保持 SFTP、后续 su 和 exit；普通用户 sudo/exit；相同目录及跨包 CWD/RemoteUser 标记。
- 启动与 root 文件读取：辅助 SFTP 就绪后重放已观察 CWD；root base64 起止标记、诊断噪声隔离、空文件和未加框输出回归。
- 传输：2 万文件 manifest 中连续条目状态变化不重分配整棵树，journal round-trip 保留完成状态；10 万文件 manifest 的 UI JSON 小于 1KiB，原始 manifest 不被破坏。
- 浏览器交互：真实 toolbar 与 transfer hook，mock 原生 bridge；验证单一上传按钮、普通文件选择、拖放目录上传路径与断线禁用，检查 Windows/macOS/Linux 样式截图。
- 连接表单：Kubernetes 预设可保存/导入并走密码认证；方法、用户名/密码、sudo/su 密码网格布局保持预期的整行与半宽排列。
- 项目门禁：类型检查、lint、Prettier、CSS contract、Tauri 全量测试、Clippy；最终结果在完成任务时记录。

## 连接启动加固（2026-09-09）

- Shell channel 创建、PTY 请求与 shell 请求统一经过可取消的启动等待。保持每步 8 秒超时，取消优先于就绪结果；用户关闭正在连接的标签后，挂起步骤立即释放，不再等待超时才退出。错误保留具体阶段，由 worker 监督层统一记录。
- 核对本地 russh 实现后确认：PTY/shell 请求的 future 只等待请求入队，不代表远端确认。对应注释改为准确描述，不将这两个步骤的超时解释成服务器未响应。
- SFTP 初始化后的完整 workspace snapshot 改用已有后台发布入口，避免连接库或传输日志 hydration 延迟 SFTP handle 交付和 shell integration。平台探测仍先于 SFTP，保留交互式网关路由判定，不冒险提前打开错误目标的文件通道。
- 新增启动取消释放、取消优先级、成功、失败和超时回归；不改变握手算法、认证方式或超时配置。
- 验证：Tauri 全量 634 项测试通过（603 单元测试、10 与 21 项集成/contract 测试）；Tauri typecheck、lint、Prettier、Clippy 与 diff 空白检查通过。未做真实远端连接耗时对照，不量化提速幅度。
