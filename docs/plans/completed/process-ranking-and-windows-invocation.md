## 约定

- 不增加 “CPU Top 40” 标题，沿用 CPU / 内存 / 命令三个排序入口。
- 采集可见进程，分别选出三个排序的前 40 条，传输去重后的并集（最多 120 条）。客户端按所选列显示 40 条，不在单一 CPU 或内存候选集中假装全局排序。
- 命令排序沿用采集端稳定顺序，通过 `commandOrder` 传递，避免服务器与客户端排序规则不一致；内存排序使用数值而非取整后的展示文本。
- CPU 保持整机口径。Linux 使用同一采样窗口的进程 tick 增量 / 全机 tick 增量，匹配 PID 与启动时间，不按 bash/awk/sh 等名称过滤真实负载。
- 仪表是真实整机使用率，不能改成前 40 条之和。未列出的进程、采样期间退出的进程、权限限制、中断与虚拟化开销，以及四舍五入均可能导致差额；不人为缩放进程值凑齐总数。悬浮说明解释该边界，不改变布局。
- Windows 本地 PowerShell 的直接 CLI/MCP 调用使用 `& 'exe路径'`。MCP 注册中的 executable 是参数，保持 `'exe路径'`，不插入 `&`；POSIX 引号单独转义。
