# macOS 原生标题栏布局修复

状态：实现与本机验证完成（2026-10-08）

## 问题

主窗口首次显示后才校准红绿灯；全屏恢复等待 140ms 后校准；窗口捕获期间系统紫色共享指示器停在默认位置。

## 实现

- macOS 配置隐藏创建主窗口，在恢复窗口尺寸、读取保存的缩放、完成原生定位后显示。移除页面加载后才定位的路径。
- 监听原生窗口 update / resize / 退出全屏及标题栏 frame 通知，在主线程同步维护几何，移除 140ms 去抖。
- 缩放值在偏好变更时刷新缓存；布局通知不读取存储。增加重入保护和几何差异检查，只有变化时才刷新 tracking areas 和绘制。
- 全屏期间交由 AppKit 管理自动隐藏标题栏；退出时恢复自定义布局。退出进程时注销观察者。
- 保留原生按钮尺寸、中心间距和缩放规则。系统共享指示器自动随正确的原生布局居中，无需依赖私有类名定位控件。
- 后续统一主窗口启动显示：Windows 配置也隐藏创建，Linux/macOS 保持隐藏；独立的 `renderer/lib/main-window-reveal.tsx` 等待主题和应用首屏提交后，再通过 Tauri bridge 显示主窗口。这样 Windows 不先露出 WebView 白底，macOS 不先露出空白 vibrancy，Linux 也有明确的首次显示路径。
- 提取 `lib/macos_titlebar/mod.rs`，由原有 `lib.rs` facade 引入。`platform.rs` 从 629 行降至 498 行，新模块 245 行；其他修改的业务文件低于 800 行，无强制拆分阈值触发。
- 补充 macOS 与跨平台启动显示契约测试，并同步架构和设计文档。

- CSS contract 通过，历史 11 个 `!important` 和约 1 个直接颜色值告警未增加。
- 跨平台启动握手后，Tauri 测试为 695 个单元测试、10 个 CLI 集成测试和 23 个契约测试全部通过。
- 从当前工作树构建 `FileTerm Dev.app`，核对版本 2.2.26、bundle ID `com.fileterm.desktop.dev`、进程路径；当前工作树 Vite 监听 5188。
- Computer Use 捕获时共享指示器居中；100% 时原生诊断中心为 `(50, 24)`，标题栏高 48pt。临时原生视图诊断代码已移除。
- 最终构建通过原生绿色按钮进入全屏，再通过 Escape 退出，捕获画面中共享指示器保持正确对齐。
- 在 UI 中切换 100% → 140%，共享指示器继续随顶栏居中，随后恢复原来的 100%。
