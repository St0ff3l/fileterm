# SSH 自动线路选择与代理线路管理

状态：方案草案，尚未实现。基于已合入 main 的 SSH 代理批量分配和 Windows 出站网卡选择。开始产品化前，先确认需求方实际使用的代理客户端、线路形态和规则优先级。

## 目标

在 FileTerm 内按服务器管理 SSH 出口。用户可以给单台服务器设置线路策略，也可以给多个服务器打同一标签并统一应用策略。自动模式探测当前可用线路，优先使用稳定且连接耗时较低的线路；线路失败时尝试其他合适线路，并记录故障线路、故障阶段和切换结果。

首个可用版本只覆盖普通 SSH Shell 建连和重连。SSH 会话内的 SFTP 继续复用同一个 SSH 会话。断开的 SSH 流无法无损迁移；自动切线需要重新建立 SSH 会话，未保存的终端远端状态不会保留。

## 当前实现基础

- `SshProfile` 已有 `proxyProfileId`、自定义 SOCKS5/HTTP 代理、`sshNetworkInterface`、跳板配置和 `tags`。连接编辑器已有标签输入，标签无需再造一套服务器分组字段。
- 代理库目前保存 FileTerm 可连接的 SOCKS5/HTTP 端点；连接时 Rust 自己建立直连或代理流。它不是 v2ray、Amnezia 或 EasyTier 的进程管理器，也不会自动遵循 Windows 系统代理设置。
- Windows 出站网卡选择已在连接级实现，支持保存适配器标识并在建连时解析索引。当前网卡选择与代理、跳板互斥；普通 SSH 网卡选择还限定 IP 字面量。
- SSH 路由解析、代理/直连/网卡拨号分别位于 `sessions/ssh/transport/route.rs` 与 `transport/proxy.rs`。自动选择应在统一的 SSH 传输规划层增加，不应让 renderer 直接建连接或探测网络。
- 应用已有结构化 connection 日志，可记录路由选择和失败，不应把代理口令、密钥或认证数据写入日志。

## 术语与规则建议

### 线路

一个线路是 FileTerm 从本机到 SSH 目标建立 TCP 流的一种完整出口方式。首批候选线路限定为：

1. 系统默认直连。
2. Windows 指定网卡直连，例如 EasyTier 虚拟网卡或 Amnezia VPN 虚拟网卡。
3. 已保存的 SOCKS5 或 HTTP CONNECT 代理端点，例如 v2ray 或 Amnezia Local Proxy 暴露的本地端口。

首版不组合代理、网卡和 Jump Host，不改变系统全局路由，不启停或改写第三方客户端配置。Jump Host 和 OpenSSH 配置别名沿用当前限制，待线路抽象稳定后单独评估。

### 策略优先级

建议按以下顺序解析服务器的有效策略：

1. 单台连接的线路规则。
2. 连接标签匹配的规则。多条匹配规则必须有明确优先级；同优先级且线路集合冲突时提示用户解决，不随机选取。
3. 全局自动策略。

已存在的 `proxyProfileId` 和 `sshNetworkInterface` 保持原行为，升级后不静默转为自动线路。用户显式启用新策略后才参与候选选择。

建议把“指定线路”建模为两种模式：

- **首选线路**：正常优先使用指定线路；其不可用时允许切换到策略内其他线路，并记录首选线路失效。
- **固定线路**：只尝试指定线路，失败时明确报错，不自动改道。

自动模式则允许在该服务器的候选线路集合内进行选择和故障切换。此处把需求里的“最短路径”解释为“端到端连接时间较短”，不使用 IP 跳数推断最短路径；代理和 VPN 内部的网络拓扑通常不可见。选择时先排除不健康/不适用线路，再偏向最近成功率高、延迟低且波动小的线路，并增加冷却和切换迟滞避免线路抖动。

## 产品化阶段

### 0. 盘点实际线路和探测方式

- 记录 Windows 上实际使用的客户端全名、版本、工作模式、接口/本地端口、目标线路和可获得的状态信息：v2ray 客户端、Amnezia VPN/Local Proxy 模式、EasyTier 客户端及其网卡/路由。
- 给每条线路准备一个授权 SSH 目标，记录目标 IP/域名、端口、预期线路以及是否能通过另一线路访问。目标特定测试比仅检测本地代理端口更能说明 SSH 是否可达。
- 验证两条不同类型线路同时建立 SSH，并验证一条线路故障时替代线路能到达同一服务器。记录抓包或代理/目标端日志。
- 明确域名目标的 DNS 行为：代理路线可由代理端解析的情形、直连指定网卡下的解析路径，以及多地址记录如何选取。未完成验证前，自动选择的网卡候选继续限定为当前已支持的 IP 字面量目标。
- 本阶段不添加产品代码。若实际软件没有可稳定观察的端口/接口状态或目标不可达证据，先收窄首版支持矩阵。

### 1. 抽象线路候选和连接策略

- 在 `packages/core` 定义稳定的线路引用、连接级策略和标签级策略类型。路由策略属于本机配置；线路健康、最近延迟和冷却计时属于运行时状态，不同步到连接导入/云备份。
- 在 Rust 新增 SSH route planner/provider 边界：候选线路负责探测、拨号、显示状态和错误分类；planner 根据 profile、标签规则和运行时健康状态返回有序候选。
- 复用现有 `ProxyProfile` 和 Windows adapter ID，不复制代理凭据或接口索引。清晰区分系统默认、指定网卡、代理端点；显示名不能作为稳定 ID。
- 在连接库/设置存储中持久化标签策略和全局默认策略；在同一锁与既有脱敏流程下保存。缺失代理或网卡引用要显示不可用并允许修正，不自动替换成默认线路。
- 保留旧连接字段兼容。对有显式代理或网卡配置的旧连接维持现有语义，直到用户明确选择自动/首选/固定模式。

### 2. 服务器和标签策略界面

- 在线路管理页面展示线路名称、类型、可用状态、最近探测时间、延迟及最近错误。没有真实状态依据时显示“未知”，不要猜测在线。
- 在服务器连接编辑器提供“自动 / 首选线路 / 固定线路”策略；标签策略提供共享的线路候选和首选顺序。
- 服务器列表支持按现有标签筛选/批量应用策略。连接级规则可覆盖标签规则；多个标签命中时展示实际命中规则，冲突时阻止含糊保存。
- 工作区或连接详情显示本次实际选择的线路，以及故障切换记录。保留用户的连接级代理和网卡旧配置展示方式。

### 3. 按目标探测、择优和故障切换

- 探测分为线路自身可用性和“该线路到此服务器”的可达性。只有端点在线不代表目标 SSH 可达；探测不要自动执行服务器命令或使用用户的认证凭据。
- 首次连接先测候选线路的 TCP 可达性/耗时，再按策略尝试 SSH 传输。运行中的实际成功/失败也更新短期健康数据。限定并发数、超时和缓存时间，避免连接列表刷新造成扫描风暴。
- 只对可归因于线路的错误切换：网卡离线、连接超时/不可达、代理端点失败等。主机密钥不匹配、认证失败、算法不兼容和明确的服务器拒绝不应通过换线路隐藏。
- 线路失败时写结构化日志：profile ID、标签规则 ID、首选/尝试线路 ID、provider 类型、阶段、错误分类、延迟、是否切换及最终结果。脱敏代理地址中的凭据和认证信息。
- 自动重连时重新运行 planner 并解析实时网卡状态。现有 SSH shell 无法在原 TCP 流上透明切线；断线后切换意味着重建会话并明确提示会话状态已重置。
- 对最近失败线路设置有时限的冷却；冷却后可小流量重试恢复。延迟接近时优先保持当前成功线路，避免频繁换线。

### 4. 第三方工具适配

- **v2ray**：首版优先把客户端暴露的 SOCKS/HTTP 本地入站登记为标准代理端点，复用现有 SOCKS5/HTTP CONNECT 拨号。探测本地监听及目标连通；自动发现动态端口或启停进程另行做版本化适配。
- **Amnezia**：区分 VPN 虚拟网卡出口与 Local Proxy 出口。不同模式不是同一个线路；按用户实际版本确认本地代理类型、端口变化和状态来源。首版用已登记的标准端点或网卡接入，不读取/改写私有配置。
- **EasyTier**：按用户现有用法作为直连组网线路，通过虚拟网卡/已安装路由到达覆盖网 SSH 地址；验证目标网段实际由该线路承载。虽然 EasyTier 也有可选 SOCKS 服务，首版不擅自把用户的直连模式改为代理模式。
- 只有在产品公开且稳定的 API/CLI、权限边界和版本兼容矩阵确定后，才增加客户端状态自动发现或进程控制。不得通过模拟 GUI 点击、任意脚本、扫描本机端口或修改第三方私有配置实现“接管”。用户停止第三方客户端时，FileTerm 只报告线路不可用，不擅自杀进程或改系统代理。

### 5. 回归与验收

- 单元测试覆盖线路策略优先级、标签冲突、候选过滤、稳定性评分、冷却恢复和错误分类。
- Rust/本地夹具覆盖直连、指定网卡、SOCKS5、HTTP CONNECT；代理失败后成功切换、所有线路失败、固定线路失败、主机密钥错误/认证错误不切线。
- Renderer 覆盖服务器与标签策略编辑、批量应用、冲突提示、线路状态、切换日志和错误后保留草稿。
- Windows 实测至少使用两种真实线路同时连接同一授权目标，断开首选线路后验证备用线路成功并核对代理/目标侧日志。再验证停用所有线路时明确失败，不出现未授权默认出口回落。
- 更新本计划记录客户端版本、连接目标、实际路线证据、错误行为和未支持模式；运行仓库规定的代码质量门禁。通过后移入 `docs/plans/completed/`。

## 首版非目标

- 对所有 VPN/代理客户端提供统一的启停和配置编辑能力。
- 自动更改 Windows 系统代理、路由表、DNS、VPN kill switch 或管理员级网络配置。
- Jump Host 与代理/网卡线路任意叠加、OpenSSH `ProxyCommand`、SSH 配置别名的自动线路规划。
- FTP、Telnet、Serial、独立 SFTP profile、全应用流量路由。
- 对已连接的 SSH 流做无损迁移；远端 shell 状态随 SSH 断线仍需重建。

## 复杂度与估时

这是跨 Rust SSH 传输、连接/标签策略存储、Tauri bridge、React 管理界面、健康状态和 Windows 实测的高复杂度功能。它不只是编写某个代理客户端 connector。

- 线路盘点与可达性探针：约 1–2 个工作日，依赖真实 Windows 线路和授权目标。
- 复用现有代理/网卡的策略核心、标签规则、连接择优和失败切换：约 7–12 个工程日，另需多轮 Windows 实测。
- 每个第三方客户端自动发现/生命周期适配：公开接口明确时约 2–5 个工程日/客户端；若依赖私有协议、提权服务或 GUI 自动化，应重新评估，不纳入首版承诺。

## 待确认决策

1. “指定线路”默认应是可故障切换的首选线路，还是永不改道的固定线路？本方案建议默认首选，并提供固定模式。
2. 自动择优是稳定性优先、低延迟作为次级排序，还是任何延迟改善都允许切换？本方案建议稳定性优先并增加迟滞。
3. 用户安装的具体客户端分别是什么（如 v2rayN/其他 V2Ray GUI、Amnezia VPN 的 Local Proxy 或 VPN 模式、EasyTier GUI/服务版本）？
4. 首版是否接受“用户先启动客户端并登记端点/网卡”，后续再逐一增加客户端自动发现和控制？本方案建议接受。
5. 首版自动网卡路线是否接受仅支持 IP 字面量；域名的跨网卡 DNS 解析留到探针验证后？
