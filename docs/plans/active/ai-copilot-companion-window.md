# AI Copilot 同窗 UI 草案

状态：进行中

## 当前决策

AI Copilot 不创建 Tauri 原生子窗口，也不使用透明桌面间隙。它是主窗口内由 renderer 模拟的绝对定位卡片：打开后压缩现有工作区，右侧出现一张完整圆角的 AI 面板，并与标题栏顶部对齐。

## 布局

- AI 面板和终端/文件工作区都位于同一个 FileTerm 主窗口内；标题栏会为右侧卡片预留宽度，终端区域同步收窄。
- 中间仅保留窄轨道与胶囊形把手，轨道从窗口内容顶部连续延伸到最底部的传输任务栏，视觉上参考微信的“同窗分区”关系，而不是独立窗口的悬空关系。
- 大多数桌面宽度下，工作区优先缩窄，AI 面板保持约 320–368px；窄窗口降为覆盖式面板，避免把终端挤到不可用。
- AI 卡片保留独立圆角、边框和阴影，但不再出现透明大缝或第二个原生窗口外框。

## UI 范围

- 仅实现 AI 面板、未配置 Provider 空状态、禁用态输入框和设置里的 Provider 表单视觉。
- 设置表单仅保存于当前 renderer state，用于查看布局；不持久化 API Key、不发送网络请求、不接模型。
- 不读取/上传终端输出、不生成真实回答、不执行或写入终端命令。

## 后续实现边界

真实 Provider、凭据存储、上下文授权、命令提议与写入终端需在后续单独设计，并通过 `core → Rust commands/events → tauri-api → renderer` 接入。

## 验收

- [x] 打开 AI 后不创建任何 Tauri 子窗口。
- [x] 同窗内右侧 AI 卡片与主工作区之间只有窄轨道和把手。
- [x] AI 设置页明确标记为界面预览，API Key 不会保存或发起请求。
- [x] TypeScript、Rust tests、Clippy、lint 和 formatter 全部通过。
